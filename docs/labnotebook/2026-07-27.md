**Saw / decided:**

  org, IO conventions). The phases and next-actions moved out; repo-org and IO
  conventions stayed, because those are reference material, not control surface.
- Went with a **flag-plus-grep** scheme for "has this run been written up yet":
  `log_analysis()` writes `[ ]`, `/lognote` flips it to `[x]`, but `/lognote` ALSO

  create the worktree by hand. Worth knowing for any future tooling that assumes a
  modern git on the login node.
- **Found while testing: `git_provenance()` silently degrades to `no-git` inside a

  `.git` is a *file* pointing elsewhere, and 1.8.3.1 predates that. Verified both
  ways on `-p dev`: worktree → `available=False`; main checkout → `available=True`,

  all real runs launch from the main checkout — but it means a definitive run
  launched from a worktree would record no commit at all. (→ scratchpad)
- `phi_manifest.py` is referenced by the spec but lives outside this repo (PHI

  the prose discipline in these files is a convention, not a gap.

## 16:45 — P0.3: the IO contract is real code now

**Ran:** no analysis — infrastructure. Installed pyarrow + joblib into the shared
venv and built the artifact layer P0.3 asked for: `io/sidecar.py` (the envelope,
parent references, staleness), `io/models.py` (joblib + sidecar), a rewritten
`io/tables.py`, and `io/__init__.py` as one flat namespace. Contract written up in
`docs/io_conventions.md`; 18 tests in `tests/test_io_conventions.py`; full suite
27 passed on `-p dev`, and every module in the package still imports.

**Output:** in-repo only (no Oak output — nothing to index).
**Commit:** see the commit that adds `docs/io_conventions.md`.
**Index:** N/A.

**Saw / decided:**

- **pyarrow does not install here the obvious way.** Sherlock is CentOS 7, glibc
  2.17; modern pyarrow wheels are `manylinux_2_28`, so plain `pip install pyarrow`
  fell through to a source build and died building `libcst` (no Rust toolchain).
  `--only-binary=:all:` makes pip back off to the newest version that still ships
  a `manylinux2014` wheel → **pyarrow 20.0.0**, plus joblib 1.5.3. With
  `--no-deps`, numpy 2.4.2 / pandas 2.3.3 untouched. Round-trip and
  single-column read both verified. The failure mode is now baked into the
  ImportError message in `io/tables.py`, so the next person gets the recipe
  instead of the Rust error.
- **Narrowed the P0.3 task on purpose**: it said "switch `save_table` from CSV to
  Parquet", which would have silently changed the format of the whole raw-voltage
  QC tree. `save_table` now dispatches on the path's extension instead — existing
  `.csv` call sites are untouched, new code calls `io.write_table` and gets
  Parquet plus a sidecar. Confirmed with Sabra that QC stays CSV. (→ DECISIONS)
- Sidecars **append** their suffix (`x.parquet.provenance.json`) rather than
  replacing it, because the replace form collapses `x.parquet` and `x.csv` onto
  one name — the exact collision the "convert one CSV when you next touch it"
  policy walks into. Readers still resolve the legacy replaced form, so the old
  pain caches under `outdated/` still trace.
- Parents are fingerprinted `(path, bytes, mtime)` + a digest for small files
  only; view staleness is defined against the cache **manifest's** digest.
  Hashing a GB-scale cache on every load would cost more than the recompute the
  check is guarding. `file_digest` refuses >64 MB so that stays true.
- **Audited every writer in the package** while wiring this up. Nine write a table
  with no provenance beside it (`summarize_exclusions`, `build_rail_summary`,
  `build_plot_targets`, `build_run_start_times`, `pad_exclusions`,
  `processing_status`, `threshold_summary`, `bipolar_bands`,
  `build_file_registry`). Not retrofitting them — same no-sweep-and-add rule as
  `log_analysis()`. The detectors/exclusions/masks already emit `params.json` and
  the plot scripts already write `provenance.json`; those are fine.
- Also wired the paths P1.1 will need, so the refactor isn't inventing them under
  time pressure: `pain_epoch_{unit_dir,cache_path,defs_path,manifest_path,views_dir}`
  keyed on (epoch definition, QC mask) — the only two things that force a cache
  rebuild — and `analysis_run_dir` / `sweep_run_dir` for the 5-level scheme.
- `features/common.py:write_run_provenance` now delegates to the shared writer
  rather than hand-rolling its own dict, keeping its plot-specific keys. So the
  existing plot scripts' `provenance.json` gains the standard envelope for free.

**Noticed, not fixed:** `config.PLOTS_ROOT` is `analysis/scratch/`, but
`architecture.md` PART 4 draws scratch as `analysis/pain/scratch/`. Left alone —
it is scratch, runs already exist at the current path, and moving it is churn
with no payoff. (→ scratchpad)

## 16:00 — P0.6 dtype audit: float32 cache validated; the real error was the accumulator

**Ran:** the new `ieeg_ehr.features.dtype_audit` (P0.6), four legs — on-disk dtype
inventory, storage round-trip, epoch-average accumulator comparison, and a full
float64 recompute of one run's PSD checked against the production float32 path.
Sample: sub-071 / sub-085 / sub-088.

**Output:** `$DERIV/qc/feature_level/validation/dtype_audit/p0.6_2026-07-27T160009/`
**Commit:** `34da3ee180a1` +dirty ← tree was dirty (P0.3 in flight in parallel),
so the recorded hash does NOT describe the code that ran. Re-run at a clean
commit if this ever needs to be citable provenance rather than a decision input.
**Index:** logged in `docs/analyses_run.md`

**Saw:**

- On disk today: `psd_log_bins` is **already float32** across all 9 files
  inspected, uniformly, gzip-4, one chunk per channel-run. Raw `ElectricalSeries`
  is **float64** — which I had assumed would be integer.
- float32 round-trips **bit-exactly** through both HDF5 (gzip 4) and Parquet
  (snappy, 390k rows, long layout). pyarrow appeared in the venv mid-session, so
  the Parquet leg ran for real rather than being skipped.
- **Headline:** a full float64 recompute vs the production float32 path agreed on
  epoch averages to **8.1 sig figs** (worst rel err 8.3e-09 = 2.5e-07 fractional
  error in linear power = 0.14 float32 half-ulps), over 400 epoch-average values,
  8 bipolar pairs, 300 windows per epoch block. float32 storage is effectively
  free.
- **The result I did not expect, and the one that actually matters:** a float32
  *accumulator* over a ~5 min epoch holds only **6.0 sig figs** — worse than the
  storage decision by three orders of magnitude, and the largest precision loss
  anywhere in the chain. Storage quantisation AVERAGES DOWN over ~300 independent
  roundings; accumulator error GROWS. numpy does not upcast for float32 input, so
  the naive `arr.mean(axis=0)` is the lossy one. → new standing rule in
  `CLAUDE.md` ("store narrow, compute wide") + `config/cache_params.py`.
- Also: worst stored log-power is **-36.8** (sub-088), only ~1.1 decades above
  float32's smallest normal → linear-domain views must exponentiate in float64 or
  a later baseline division can underflow to exactly zero.

**Broken / worked around (both were bugs in the audit, not the data):**

- First full run picked each subject's **smallest** raw run for the recompute leg,
  on the theory that precision doesn't depend on run length. It doesn't — but the
  smallest run is a **dead** one (single constant voltage repeated → PSD 0 →
  log10(0) = -inf everywhere), so the leg had nothing finite to compare and
  silently reported "not run". Now filters to runs ≥ one epoch long and walks
  candidates until one yields finite data, recording what it skipped.
- The first verdict **failed** the whole audit on the 6.0-sig-fig accumulator
  result, which is wrong: that is a constraint on the VIEW layer, not evidence
  against float32 storage. Conflating the two would have argued for a 2x larger
  cache while leaving the actual error in place. Verdict now reports
  `float32_storage_validated` separately from `view_layer_requirements`, and only
  the former can fail the run.
- Leg C originally loaded a whole session's PSD at once, copying
  `build_pain_epoch_power`'s pattern — that's 80+ runs and ~15 GB for sub-085.
  Now streams run-by-run with logged caps.

**Spawned:**
- decision → `DECISIONS.md` 2026-07-27: cache float32, views float64, with the
  storage-vs-accumulator reasoning.
- scratch → `SCRATCHPAD.md` ×3: all-`-inf` stored PSD runs; the -36.8 log-power
  outlier; `io/nwb.py`'s float32 voltage cast is measurably not bit-exact.

**Refs:** PLANNING P0.6 (done) · DECISIONS 2026-07-27 (cache float32) ·
`config/cache_params.py` · `docs/view_registry.md` (precision rule)
